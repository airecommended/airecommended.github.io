调用 API 中转站出现报错该如何排查？

2026-09-03

调用 API 中转站报错时，排查需从“客户端配置”、“网络与连接”、“中转站服务”及“目标模型”四个维度进行逐项排查。具体排查路径如下：

一、 排查客户端配置（最常见）

  1. API Key 鉴权错误（报错如 401 Unauthorized）
  2. Base URL 配置错误（报错如 404 Not Found、路由错误）
  3. Model ID 错误（报错如 “model not found”）
  4. 配置文件格式错误

二、 排查网络与连接问题（报错如 超时、连接被拒绝）

  1. 网络不通或 DNS 解析失败
  2. 客户端超时设置过短
  3. 代理或本地环境拦截

三、 排查中转站服务状态（报错如 5xx 错误、服务不可用）

  1. 中转站服务异常或维护
  2. 账户或配额异常（报错如 429 或 insufficient_quota）
  3. 接口格式不兼容

四、 排查目标模型与接口（报错如 模型未启用、参数错误）

  1. 目标模型已停用或不支持
  2. 请求参数错误（报错如 400 Bad Request）

排查建议：优先通过中转站控制台的“接口调试”功能或 curl 命令测试基础连通性，再结合客户端日志中的完整报错信息（如 HTTP 状态码、错误码、错误消息）进行精准定位。
